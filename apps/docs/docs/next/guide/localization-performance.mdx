# Localization and performance

## Versioned runtime copy

The runtime catalog contract is `a3s.dev/form-locale-catalog/v1`. English and Chinese ship with the package. An embedding host may replace individual messages without changing a form revision or digest.

```tsx
import {
  FORM_LOCALE_CATALOG_API_VERSION,
  type FormLocaleCatalogOverride,
} from '@a3s-lab/form/core';

const localeCatalog: FormLocaleCatalogOverride = {
  apiVersion: FORM_LOCALE_CATALOG_API_VERSION,
  messages: {
    selectPlaceholder: 'Choose a workflow model',
    actionFailed: 'The node was not saved. Check the workflow service and try again.',
  },
};

<FormRenderer
  plan={plan}
  value={value}
  locale="en-US"
  localeCatalog={localeCatalog}
  onChange={setValue}
/>;
```

React, Vue, Web Components, and Designer preview use the same catalog. It covers runtime controls, data-source states, progress, validation summaries, schema errors, and async-validation fallback errors. Labels and explicit document copy remain authored content.

## Field subscriptions

The compiler records rule dependencies and a subscription list for every node. A field subscribes to its own value, rules that target it, and declared dependencies for its data source. Dynamic templates such as `routes.*.match` resolve with the current row indices before comparison, so sibling repeater rows do not share one broad value subscription. React can then skip unrelated field renders without losing the latest whole host value in callbacks.

Custom node-registry renderers receive the entire form value and remain conservatively unmemoized until a dependency contract is available.

## CI budgets

`bun run test:performance` measures compilation, validation and computed values, incremental computed updates, and server rendering.

| Nodes | Compile | Validate and compute | Incremental compute | Server render |
| ---: | ---: | ---: | ---: | ---: |
| 100 | 100 ms | 50 ms | 15 ms | 150 ms |
| 500 | 300 ms | 300 ms | 50 ms | 800 ms |
| 1,000 | 700 ms | 1,200 ms | 120 ms | 1,800 ms |

The benchmark runs after the package build as part of `bun run check` and fails CI when a median exceeds its budget.
